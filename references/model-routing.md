# 模型分工、跨模型爽点母本与三套高冲击编译模具（Wan3.0 / SD2.0 / H3）

本页是当前工作区的模型分工、跨时长爆点切分与提示词编译规则。**顶层爽剧母本（`thrill_plan`、段级三拍弧线 `dramatic_arc`、外化大动作、大反差景别、≤12字切片金句、人物身份与现实背景）全模型共用**；模型分支只负责**按各自时长法则切分 + 套用对应模型的高冲击编译模具**。默认不为同一段预写三套冗余长文，但切换模型时绝不允许把已锁定的金句、反杀动作或景别硬切转写丢。

## 一、模型分工与触发

| 模型 | 用途与节拍定位 | 请求时长 | 开始条件与引用语法 |
| --- | --- | --- | --- |
| **Wan 3.0** (`wan3`) | 主力，承载完整**「痛点起手 → 施压极限 → 骤切反杀+金句+尾钩」**三拍闭环 | 每次固定 **30秒** | 默认编写；引用写 `图1、图2…`；付费提交需用户授权 |
| **Seedance 2.0** (`seedance2`) | 单核高能爆点；将30秒闭环精准对拆为**「前15秒蓄压断钩段 + 后15秒宣泄反杀段」** | 每次固定 **15秒** | 用户指定切换或试拍SD2.0时启用；引用写 `@图片1、@图片2…` |
| **H3** (`h3`) | 替换Wan3/SD2.0成片中的局部瑕疵，或单点爆破高难度核心动作链 | **4–15秒**（或双15秒组合包） | 用户明确提出处理瑕疵或指定H3时开始；引用写 `<Picture 1>` + 官方英文六字段 |
| **Seedance 2.5** | 后续复杂打斗、多主体调度与复杂特效候选 | 主生成目标同为30秒，待核验 | 当前未启用，不因出现打斗便自动切换 |

审核可指出成片问题；用户未提出处理时，不主动改写H3补镜提示词、建立补镜任务、提交或抽卡。用户提出文案修改或处理方案不自动等于付费提交；已有明确提交授权的同一范围不重复询问。Wan3生成授权不覆盖H3或Seedance，不设自动跨模型付费回退，不把“抽卡”理解为无限重试。

## 二、30秒 (Wan3) ↔ 15秒 (SD2.0) ↔ 短镜头 (H3) 爆点对齐切分铁律

三个模型单次时长不同，**严禁把30秒剧情机械除以2平摊成两个温吞的15秒，也严禁为了凑30秒拖慢台词或塞无聊过场**：

1. **Wan 3.0（30秒三拍闭环 + 中段强制唤醒）：**
   - 30秒是Wan3一次请求的总时长，段内必须包含 **3–5个大反差景别摄影镜头**。
   - **标准节拍分布**：`0–8秒`（痛点/挑衅暴击入场，前3秒必见冲突动作） → `8–18秒`（施压升级、逼至绝境或亮出赌注） → `18–30秒`（骤切反杀 + ≤12字重锤金句落点 + 对手受击/悬念尾钩）。
   - **第15–20秒强制设“视觉唤醒锚点”**：Wan3在15秒后极易动作衰减变成站桩聊天，因此第15–20秒之间**必须安排一次景别大跳切（如中景骤切极特写或低角度仰拍）+ 高幅度肢体/特效爆发动作**，强行拉高后半段动态权重。
2. **SD 2.0（15秒单核爆点 · 蓄压/宣泄双段对拆）：**
   - 1条30秒Wan3闭环 ⇄ 精准拆为2条15秒SD2.0（`seedance_groups`）：
     - **前15秒（A段·蓄压断钩段）**：`0–3s` 痛点暴击起手 → `3–12s` 挑衅加压推向极限 → `12–15s` 主角眼神骤变/抬手扣腕/法器微鸣（**必须卡在反击即将爆发的前一秒断钩！**）。
     - **后15秒（B段·宣泄反杀段）**：`0–3s` 同轴硬切出手/底牌砸落 → `3–11s` 实力碾压反杀 + 重锤金句落音 → `11–15s` 对手震退跌坐/全场死寂余波。
   - **15秒切分三条铁律**：① 第15秒分界点必须卡在悬念或动作起手峰值，禁止切在平淡聊天中段；② 单条15秒只放 **2–3个镜头（单镜4–7秒）**，靠**动势接力**（顺拍桌抬手势急速上摇、借挥袖同轴硬切）串联；③ **单条15秒总台词严禁超过38字**（留足4–5秒纯动作与物理反馈时间），且严禁把同一句台词劈在两条15秒请求里。
3. **H3（4–15秒单点爆破）：**
   - 直接从已审母本中截取对应秒数的核心动作镜头（如截取5秒拍案震飞茶盏、8秒法相亮起威压），继承前后入出态，不重新发明慢节奏铺垫。

有用的独立H3模块保留在`units`；已被当前Wan3/SD2.0稿替代的旧源镜默认用于对照，用户明确要求只保留最新时，先将当前段改为直接定位原件或现行剧本，再删除重复源镜及过时绑定。历史提交按冻结快照保存。现有本地编写与看板支持在同一制作数据内设置`active_model: wan3`（读取`generation_groups`）或`active_model: seedance2`（读取`seedance_groups`）：每段记录`source_locator`、`dramatic_arc`（三拍弧线）、连续覆盖全时长的`shots`、`dialogue_events`、实际图片`references`与完整中文`prompt_text`。源分镜修订不匹配时校验拒绝，须先同步；组合段的页面编辑保存在该段`editor_draft.values`。视频提交已支持wan.coolhs.com原生买家协议（`generation.protocol: wan-portal-v1`）。

## 三、三套模型的「高冲击提示词编译模具」（头部减脂、动作优先）

### 分模型打斗动作密度红线（防喂撑出残影）

视频模型处理高速肢体交缠有物理容量上限。凡涉及打戏的生成单元，严格受以下密度红线约束：
- **Wan 3.0（30秒打戏段）**：全段硬限 **3–4 个独立交锋回合**（每回合 5–8 秒，遵循 `蓄势起手 → 碰撞顿帧爆点 → 受击位移撞物`），**全段最多 6–7 个摄影镜头**，单镜严禁超过 2 次近身格挡；第 15–20 秒强制安排“破防/战局逆转”大跳切。
- **SD 2.0（15秒打戏段）**：全段硬限 **1–2 个高能交锋回合**、**最多 4 个摄影镜头**；固定按**「前15s：强攻压迫 + 被逼到边缘/起手亮招（卡在出招前0.5秒断钩）」+「后15s：硬切破招反杀 + 撞碎物件 + 烟尘战损收尾」**对拆。
- **H3（4–15秒补镜）**：单段专注 **1 个核心接触点**（如 5 秒断刃/破盾/震飞），用精确毫秒切点 `At 00:xx.xxx,` 钉死命中与受击瞬间。

**核心防平淡原则：视频模型的前100字注意力最宝贵！严禁在提示词开头背诵长篇材质论文（如“轻微皮下散射、低对比纹理、桌脚与马扎落下接触阴影”），必须把Token权重夺回给「大反差景别 + 外化强动作 + 情绪极值」！**

### 1. Wan 3.0 专属模具（30秒 · 中文 · `图N`）

编写前参考[官方Prompt指南](https://help.aliyun.com/zh/model-studio/wan3-video-generation-prompt-guide)，调用前核对[官方API参考](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)。

- **头部极简限制（硬限 ≤90–110字）**：
  `30秒，16:9，[强情绪题材基调]。图1[角色A脸型衣装]，图2[角色B]，图3[实景场景与主光冷暖反差]。人物保持半写实3D CG与实景共用透视受光。`
- **分镜段强动词公式（有序覆盖0—30秒）**：
  `[起止秒]。[冲击景别/机位变化]！[画左/画右人物 + 高幅度外化动作 + 器物/光影物理反馈]。`
  `[说话人]，[情绪极值+语速重音变化]，普通话原声：“[脱水短台词 / ≤12字重锤金句]”`
- **禁忌**：不套用H3六字段、`<Picture N>`和保留分析语法；不在镜头里写“眼神微冷、手指轻动”等无效微表情；不在头部重复罗列静态五官参数。

### 2. Seedance 2.0 (SD2.0) 专属模具（15秒 · 中文 · `@图片N`）

依据[Seedance 2.0官方说明](https://seed.bytedance.com/zh/blog/official-launch-of-seedance-2-0)与[Seedance 2.0提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-0-prompt-guide?lang=zh)组织正文：

- **头部极简限制（硬限 ≤75–95字）**：
  `15秒，16:9，[强情绪题材基调]。@图片1[角色A]，@图片2[角色B]，@图片3[场景与道具]，共用[主光与冷暖反差]。[画左对画右初始对峙方位]。`
- **2–3镜动势接力公式（覆盖0—15秒）**：
  - **镜1（0–5s，痛点/出手暴击）**：以特写物理冲击起镜（如拍桌、亮契印、扣腕），顺动作方向急速上摇或拉出双边对峙中景；
  - **镜2（5–11s，同轴硬切加压/反杀）**：借上一镜挥手/踏步动作在动势中硬切，触发重锤金句与最强物理/光效反馈；
  - **镜3（11–15s，震惊余波/悬念断钩）**：切对手失衡受压或新危机骤现，卡在最高张力处收尾。

### 3. H3 专属模具（4–15秒 / 双15秒 · 官方六字段英文 + 中文译文 · `<Picture N>`）

收到用户H3处理要求后，定位替换范围及可剪接前后点；读取[H3官方技能与模式指南](h3-prompt-practice.md#官方技能与读取顺序)，按完整六字段转写：

- **风格与动作100%物理隔离**：把人物身份几何、BJD半写实CG材质、实景光影全部写入 `subject_definitions`、`summary` 和 `retention_analysis` 三个字段；
- **`detailed_description` 零材质套话、全用高爆发英文强动词**：
  - 开头仅用1句简短英文点明媒介与 `<Picture N>`，随后立刻进入 `[Shot 1]`；
  - 每个 `[Shot N] At 00:xx.xxx,` 首词直接上**大反差景别 + 强力英文动作动词**（如 `Extreme close-up slamming into a low-angle medium shot as <Subject 1> slams the palm onto the table, rattling the teacups...` / `lunges`, `snatches`, `shatters`, `recoils`），严禁在Shot正文里再次赘述 `porcelain skin, BJD texture, contact shadow`。

### 创作内容迁移核对（切模型不掉爽感五条铁律）

模型转换只改变**语法外壳、引用标签与15s/30s段界**，顶层爽点母本与外化表演100%锁死。切换 `active_model` 时逐项核对：

1. **切片金句与核心爆点零丢失。** 顶层 `thrill_plan.slice_highlight` 中的重锤金句与核心反杀动作，必须一字不差地落在当前激活模型（Wan3 / SD2.0 / H3）的生效提示词里；`build_board.py` 会自动校验金句是否存在于生效正文，缺失直接报错。
2. **外化大动作与景别硬切不缩水。** 原母本设计的“拍桌震物、指鼻逼视、扣腕反压、极特写骤切仰拍”在转写时必须完整保留，严禁为了省字数缩写成“两人争执、气氛紧张”的情节摘要。
3. **头部减脂与台词容量合规。** 转写后检查提示词头部（第一个镜头时间戳之前）是否控制在字数红线内，检查SD2.0单段台词是否≤38字、Wan3单段台词是否≤85字，超标立刻脱水。
4. **身份、画内人数与情绪估时同步。** 四视角整图对应唯一角色，画左/画右方位词直接融进动作句；保留逐句的情绪极值、语速重音与跨切词句落点，同一句只有一次连续发声。
5. **独立请求的首尾动势接点。** 30秒拆为两个15秒SD2.0段时，A段末镜（12–15s）的出态（座位/脚位、朝向、抬手相位、持物、光效）与B段首镜（0–3s）的入态必须严丝合缝，不能仅写“接上段”而省掉起态动作。

用户要求英文Wan3正文时，在该段`prompt_text_en`保存完整英文并设置`prompt_language: en`，`prompt_text`仍保留完整中文；同步中文时一并更新英文。

## 四、特效设计与接口边界

先按[动作与特效](action-vfx.md)确定动作因果以及造型、材质、明暗层次、运动节奏和环境受光，再编译进对应模型模具；模型切换不改变能力性质或胜负。当前工作台已支持wan.coolhs.com的`wan-portal-v1`（Wan3 30秒）提交、查询、原图上传和下载；H3继续支持RB v1与SparkCine；Seedance2.5尚未接入。密钥只存内存/环境变量；新任务冻结当次模型、接口、完整正文、图序与哈希、时长和源修订，历史请求与成片不改写。

### 万万工作台提交要点

原生协议读取[服务文档](https://wan.coolhs.com/docs)及`/openapi.json`。使用`/api/portal/jobs`的完整提示词、30秒、16:9、所选清晰度、`audio: true`、`copies: 1`与`promptExtend: 0`；图片经签名直传与commit取得ID，按原图序设置`kind: image`、`role: ref`、`token: 图N`。稳定任务ID由本地队列请求ID派生，结果不明先查询，不新建ID盲重发。候车与生成分别显示；平台发车时间为空时不许诺完成时间。

用户更改已提交内容时，原快照保持原样。该接口不支持修改提示词；只有在用户要求替换且上游允许取消候车时，先取消并确认返还额度，再登记新版本；已发车不能伪称可退。卡密可由指定环境变量或`submit.py --key-prompt`无回显输入，经本机接口仅保存在服务内存；不写文件或命令行。当前入口会优先复用本工作区已启动的新队列看板，避免终止旧页面或丢失编辑。
