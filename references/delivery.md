# 制作数据、素材与终审看板

新制作遵循[模型分工与时长](model-routing.md)：Wan3每次30秒主生成，指定SD2.0时按15秒蓄压/宣泄双段生成，用户提出后才开始H3局部瑕疵补镜。本页注明H3的字段和短时长是既有/补镜分支，不是新制作默认值。Wan3组合段、SD2.0双段、中文正文、图序与原位编辑已支持；不能将旧H3数据直接改为30秒绕过校验。

## 素材

先规划本场面，再选本单元最少足够的身份、道具与空间参考。复用已合格且衣装、物件和场景状态适用的图，不按镜数或动作时点逐镜生图。默认使用免 Key 内置生图工具（如 Codex 内置 `image_gen`），不擅自切换需付费 `OPENAI_API_KEY` 的 CLI 通道。资产落盘须复制原始全尺寸输出（横图不低于 `1672×941`），严禁将对话流预览缩略图（如 `512×288`）存为正式素材。

### 人物四视角设定图（`character_sheet`）
- **版式与用途：** 按[版式母版](../assets/character-reference-layout-r2.png)输出无白边 16:9 横图（左 1/3 正面全身、中上正面近景、中下侧/斜侧近景、右 1/3 背面全身；同一身份与当前衣装，全身头脚完整）。人物四视角整图直接作为当前模型的身份图片，四区只代表同一身份，不代表四个人或镜头，不锁站姿与棚拍背景；人物剧情图及独立画风卡不作输入。
- **人物风格与身份依据：** 生图前查看本项目已确认人物图和视觉风格参考，并同步套用[视觉画风库](style-presets.md)对应画风的「生图美学注入配方」；[版式母版](../assets/character-reference-layout-r2.png)仅用于四视角排布。脸部几何、发型、衣装与头身比例取角色本人的身份依据，表面材质与渲染质感取已确认风格参考与生图配方。换画风本身不授权改变五官；只调整画面时继续使用原身份图，不能用参考片演员长相重建角色。
- **高定概念审美与三点雕塑棚拍布光（拒平光证件照与土味 NPC）：**
  - **影视选角级骨相与气质去土气**：主角精雕骨相立体度、干净眼面比例与空气感分层发丝剪影；配角/中老年保留本人真实年龄、皱纹骨相与体态特征，但服装与妆发用克制的低饱和/莫兰迪配色、合身剪裁与利落发式去除土气与廉价感；灵异或反派角色走高级暗黑志怪美学（清瘦有戏的骨相、层次破损剪裁），杜绝橡胶塑料僵尸感。任何角色的服装提示词至少写明 **2–3 种材质对比**（如哑光呢料/粗麻/软皮革搭配金属细扣、玉饰或垂坠轻纱）与 **1 处视觉记忆点**，严禁纯色光板塑料衣。
  - **人物图底色**：四视角、全身与面部单图、表情参考图固定使用干净、低饱和的浅色背景。同组各格写明并沿用同一底色，可选浅暖灰、象牙白或淡灰蓝。银发、白衣角色可用稍有明度差的浅灰蓝或浅暖灰衬托。拼图交付前核对各格底色一致，发丝、肩线和浅色衣缘仍清晰可辨。
  - **三点雕塑棚拍布光**：背景单独控光，人物面部保留自然明暗层次。强制使用 **45° 柔和塑形主光**（雕刻颧骨、鼻梁与下颌清晰明暗过渡） + **清晰发丝与肩线轮廓逆光（Rim Light）**将主体与背景拉开层次 + **通透双点眼神光（Catchlights）**；四视角保持同一光向与一致曝光，皮肤保留柔和次表面细微变化，高光严格服从皮肤和衣料各自粗糙度。
- **免 Key 分步生图与无损拼接（防四格像素稀释）：** 单张四格中各区域可用像素有限，按工具实际返回的原生尺寸判断细节是否足够。新建重要角色优先采用双通或四通分步生成（先出正/背全身并保留在上下文锁定五官衣装与光向，再出正/侧面部近景特写），通过 [`stitch_character_sheet.py`](../scripts/stitch_character_sheet.py) 无损拼接为 `3344×1882` 或 `3840×2160` 的 16:9 四视角整图；仅当单次直出经 100% 放大核验虹膜、睫毛、碎发与衣纹均清楚自然时才可直接采用。

### 角色表情参考

身份图固定本人长相、比例和衣装；表情图提供这个人如何自然表演的依据，不能用表情幅度重塑脸型。按需制作同角色、同角度、同光照的表情图，以中性状态为基准保持五官位置、面颊及下颌体积一致。当前采用八表情时用上四下四的等大八格：上排平静、浅笑、冷笑、压怒；下排微讶、失落、大笑、欣喜。核验格数、顺序和本人辨识度，不能因标题相同就判定表情合格。

大笑时眉间放松，眼轮匝肌与面颊随笑自然收起，下颌放松打开，牙列随口腔透视呈现；欣喜可用明亮放松的眼神与自然闭唇笑区别于大笑。逐格检查眉、眼、颊、唇的联动、左右轻微差异及变化幅度，避免把所有情绪表现为瞪眼、拧眉或横向拉嘴。表演仍按当句目的、情境和情绪起落设计，不能将一格静态表情或嘴形固定整段对白。

同一角色的表情图可跨镜头、跨集复用；同脸不同衣装或形态可共享表演依据，衣装仍取对应身份图。不同角色分别制作，不能共用一张脸约束表情。八格并非全部剧情情绪，未覆盖时按当前场面设计。默认只供创作与成片审核使用，不自动加入视频输入；只有用户要求且接口支持时才另核对其用途、输入数量和图序。保留最新确认版及可复用的生成说明，淘汰失败稿和已被替代版本，不改写实际提交记录。

### 无人物场景图与道具图（`background` / `prop`）
- **场景、道具定位与电影静帧构图（拒游客照与售楼处效果图）：** 背景图无人物，结合[视觉画风库](style-presets.md)对应画风的生图美学配方，按电影摄影静帧而非平视监控/手机游客照构图。禁止 `1.6m` 平直站拍与居中对称楼盘效果图；采用三分法、斜角纵深引导线或高低落差透视，明确建筑结构、机位与干净的表演空间。默认模拟电影定焦光学感（如 `35mm / 50mm cinema lens, f/2.8–f/4` 适度景深），除非分镜硬性需要全景深，否则不要求全屏同等死锐的高频碎噪点。道具图只放本镜相关物件，用突出形制、材质与手工细节的质感背景照明呈现。
- **电影色彩脚本（60-30-10）与情绪光影雕塑：** 按昼夜、天气、场景和已确认视觉参考制定明确的主色/辅色/点缀色（60-30-10）与冷暖分离，避免廉价高饱和手机 HDR 脏绿、惨白死顶光或发闷泥调。外景白天优先低角度清晨/斜阳穿叶光感（暖金受光面与轻柔斑驳光影 Dappled Light、轻盈丁达尔空气层次 vs 冷青蓝树荫阴影）；室内与夜景以窗外冷青夜色/天光对抗室内局部琥珀暖光视觉重点。写清主光方向、环境补光来源、自然光衰与接触阴影；亮部过渡柔和且材质固有色可辨，湿地、玻璃和金属高光严格服从材质粗糙度与光源位置。
- **三层空间、影视置景陈设与精炼提示词（90–150词）：** 按「微虚化极前景框景（枝叶/门框/廊柱） → 锐利扎实的干净中景表演区 → 空气透视与柔和薄雾自然降反差的远景纵深」组织精炼英文提示词，保留舒展的大色块与适量留白，不以全画面高反差杂纹和逐片碎叶堆砌假细节。**影视级置景陈设（Set Dressing）**：核心陈设与道具须带年代包浆、材质对比与少量叙事小物件（如老木包浆、暗纹布料、泛黄线装书册、粗陶青瓷、铜器与自然落叶），杜绝光秃秃素模与无关家电杂物；**凡画面含布幌、匾额、招牌或符箓文字，必须明确写成手写毛笔书法/旧木阴刻/做旧手绘质感，严禁出现电脑黑体或现代印刷字。** 提示词可自然带入负向排雷词以规避游客照、过度锐化手机 HDR、地产效果图、廉价高饱和绿与平光感。
- **基础场景与局部变体：** 新场景或整体画风重建时，先用文生图确定空间、真实质感与光色。同一场景仅有道具、陈设、装修、损毁或局部状态变化时，使用当前选定的基础图进行图生图，明确变化范围，保持机位、建筑结构、未变物件和光照一致；不能分别文生图导致场景漂移。多个局部变体分别从同一基础图派生，避免连续编辑累积偏差。光影方向、空间结构或大面积材质不达标时，修订提示词后重新建立基础图。重做影调时明确旧图仅提供建筑、机位和陈设依据，目标光色另取已确认视觉参考，不将旧图的发闷影调作为保留要求。批量重做风格前，先生成一张有代表性的场景验证整体光色与材质，再扩展到其余场景；验证与重试仍受本次授权范围限制。

实际打开图片，先在适合观看的缩小尺寸对照已确认视觉参考，检查整体明暗、材质色彩区分、远近层次、视觉重点及表演区是否清楚；再按100%原始像素核验分辨率（`>=1672×941`）、五官衣纹和石木绿植的真实细节。画面虽锐但发闷、满屏纹理抢眼、阴影粘连或高光泛白，均不能仅凭像素和细节判合格。两层检查均通过才把 `verified` 设为 `true`，此标记只表示素材核验，不代替用户终审或实际视频验证。图片与分镜冲突时修图或绑定，不倒改分镜。计划中的资产可记录，但 `path` 为空、`verified` 为 `false`，看板显示待补，不伪造本地路径。新角色身份设计仅为当前原件所需，不新建与本剧无关的角色设定。

## 同一数据源

作品按[专属技能机制](project-skills.md)保存长期创作方法，具体剧本、爽点骨架、镜头与提示词只在各集数据中维护。每个作品/剧集保存一份 `制作数据.json`，由[空白数据模板](../assets/production-template.json)起步。source 为原件路径，所有相对文件路径相对制作数据文件。原件不改写；分镜每单元的 source_locator 指向原件页码、段落或镜号，便于联审。多份依据放 additional_sources 列表。

顶层：project、episode、title、source、additional_sources、aspect_ratio、**style_name**、style、director_style、**thrill_plan**、review_status、pending_items、references、units（及 `active_model` 对应的 `generation_groups` / `seedance_groups`）。
- **style_name / style（画风锁，建剧未指定必提问）**：按[视觉画风库与自定义画风锁](style-presets.md)填入用户选定的内置画风标签（如 `r2混合媒介` / `2D厚涂韩漫` / `3D国漫玄幻` / `新中式水墨` / `电影写实真人` / `暗黑赛博霓虹`）或自定义画风名称与完整视觉描述；看板顶部将直接显示 `style_name` 标签。
- **thrill_plan（集级必填爽点骨架）**：包含 `opening_hook_3s`（前3秒痛点/异象钩）、`core_pain_point`（核心受压痛点）、`payoff_climax`（情绪宣泄/反杀爆点）、`thrill_level`（爽点强度1–10）、`slice_highlight`（10–15秒切片名场面+引号括起的≤12字重锤金句；脚本自动核对该金句在当前激活模型生效提示词中100%落地）、`ending_hook`（集尾最后3–5秒断钩）。
- review_status 只用 draft / reviewed / user_approved；reviewed 表示Agent统一审阅完成，绝不等于用户已批准。用户明确批准后才记 user_approved；任何内容改动先回 draft，局部复核完成后回 reviewed，需再次由用户终审。无实际视频时始终不写成片通过。

references 每项：id、type（character_sheet / prop / background / video_reference）、path、purpose、verified。风格调整使用当前确认图片与文字，不添加风格视频输入；视频参考只用于用户另外明确授权的动作、运镜等用途，使用本地MP4。图片与视频分别按实际上传顺序编号为Picture和Video。视频只作视觉参考时，单元设置 `mute_reference_video: true`，不冒充已核验原声。只有当次接口支持视频参考时才可绑定，未实现视频参考的接口会在登记任务前拒绝。units（以及 `generation_groups` / `seedance_groups`）每项：

| 字段 | 内容 |

当前工作台的 prompt 字段用于H3 Ref2VA，依次为 subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music；风格材质锁死在前三字段，`detailed_description` 全用高爆发英文强动词。Wan3在同一制作数据的 `generation_groups` 保存完整中文 `prompt_text`（头部≤90–110字）、实际“图N”图序、0—30秒的 `shots`（含第15–20秒视觉唤醒切镜）与 `dialogue_events`（总台词≤85字），设置 `active_model: wan3` 后由看板展示与编辑；SD2.0在 `seedance_groups` 保存15秒蓄压/宣泄双段中文 `prompt_text`（头部≤75–95字，“@图片N”引用，2–3镜动势接力，总台词≤38字），设置 `active_model: seedance2` 后展示；独立H3模块留在 `units`。

## 一轮统一审阅（含平淡度一票否决）

完整稿与实际素材齐备后集中核对：

- **默认短剧爽点提纯与主线守恒：** 在保留原件核心人物关系、能力底层规则与主线胜负的前提下，核对是否已砍掉寒暄水词、把痛点/异象前置到前3秒、将平淡对白升级为“挑衅→加压→反杀+≤12字重锤金句”（除非显式设置 `strict_verbatim: true`）。
- **平淡度一票否决四条红线：** ① 第1段前3秒必有痛点羞辱、危机或异象暴击（禁空镜/日常寒暄开场）；② 静音看画面动作也能看懂谁在压迫、谁反杀了谁（禁用“眼神微冷、手指轻动”等微表情充当主动作，强制外化为拍案、指鼻、扣腕、震退、强高低差构图与大反差景别硬切）；③ 提示词头部减脂达标且台词不过载（Wan3头部≤110字/台词≤85字，SD2.0头部≤95字/台词≤38字，H3镜头正文零材质套话）；④ `thrill_plan.slice_highlight` 中的重锤金句与核心爆点100%落在当前激活模型正文中。
- 中文导演稿与当次模型正文表达同一过程，镜头、切点、对白及声源一致。Wan3主段固定30秒（含中段视觉唤醒切镜），SD2.0固定15秒（蓄压断钩与宣泄反杀对拆，第15秒切在反击起手瞬间），H3补镜仅覆盖用户指定范围。
- 人物、空间方位（画左/画右并入动作句）、视线、摄影、特效、声音与相邻动势接点成立。
- 实际图片已查看、用途正确、图序与当前模型引用一致（Wan3“图N”、SD2.0“@图片N”、H3 Picture标签）。
- 按主技能八条创作约束及[官方对照审核](h3-prompt-practice.md#官方对照审核)逐项检查并直接修正文稿，不为每个步骤输出报告或评分。完成后设 reviewed 并导出。

## 拍法概述与三拍爆点展示

每个本次制作或修订的单元在联审完成后，依据生效正文提炼一句 `directing_summary`（拍法概述）及 `dramatic_arc`（三拍爆点弧线），放在看板标题下。用人名和强力外化动词，按播放顺序串起关键动作、大反差景别硬切、重锤金句表现以及动作结果；保留有辨识度的切点，不复述衣装、风格术语或剧情背景，不用“电影感、强张力”等空洞形容词代替实际拍法。

对照正文逐项确认概述提到的动作、切镜和台词表现确实存在，顺序相同；尚未写进正文的用户改法或创作意图不能先写成已生效概述。它用于审阅计划中的拍法，不代表实际成片已执行到位，也不进入提交模型的六段正文。后续改动镜头时同步更新概述。旧数据没有此字段时仍可打开，不自动拿标题或剧情摘要冒充拍法。

默认只交付文字概述和下方完整中文提示词，不为速览生成动态预演、灰模、分镜草图或临时配音；需要这些产物时由用户另行提出。

## 导出

```powershell
python <技能目录>/scripts/build_board.py <制作数据.json>
```

默认在数据同目录生成 `打开看板.html`；`--output <路径>` 可另定位置，`--check` 仅检查不写文件。未审稿和缺图仍可导出如实标注的预览；`--final-review` 要求统一审阅完成、必填正文齐全、原件及已绑定图片存在且已核验，生成“待用户终审”看板，不授权生成视频。

看板采用深色紫灰工作台形式：左侧功能导航、中间剧集列表、右侧混剪台 / 剧本 / 资产库 / 制作任务。静态与内嵌分镜看板均支持原地高清图片灯箱（可切换 100% 原始像素与复制重画指令）、展开全部 / 单镜切换、键盘 `←`/`→` 切镜及单镜审阅状态打勾；工作台侧支持独立资产库总览、右侧贴边同屏视频对照、版本星标/穿帮打标、混剪入出点快捷键（`I`/`O`）、一键导出 `.srt` 字幕及批量汇总同步。顶部显示实际时长、单元数、图数、风格及状态。图片与原件链接转换为有效本地相对路径。正文、路径中的特殊字符需转义；无变化不重写输出。

默认不导出第二份Markdown、TXT、执行包或审查报告。不因缺图声称完整终审包；先交付预览并继续补齐授权范围内的资产。只需文字任务时不强制生成图片。

深色工作台三栏布局、资产库、混剪导出与队列逻辑在工作区 `tools/studio` 中维护；基础模板历史[MIT许可](../assets/laoli-MIT.txt)保留。本技能的导演方法独立编写，风格参考入口见 directing.md，不复制外部整套规则。

## 制作工作台与视频提交

**模型与接口时长规则：** 新主生成使用 Wan3（固定 30 秒），指定 SD2.0 时按 15 秒蓄压/宣泄双段生成；H3 只有用户提出处理瑕疵或明确指定后才按实际短片段时长编写，不为凑固定档位追加空镜或拉长对白。接口支持能力以当次选择的服务商模型目录及本地 `tools/studio` 适配实现为准，不能据预设或域名推断模型范围。已提交请求和成片保留冻结快照，不因新规则自动重发。

实行 **一剧一看板**：每部正式作品在其目录自带独立启动脚本 `<作品名>/启动制作看板.cmd`（调用共享 `tools/studio/launch.py --project "<作品名>"`），每部作品自动分配并复用各自本机端口、只扫描加载本剧 `制作数据.json`；根目录 `启动制作看板.cmd` 作为作品选择入口（支持 `--project` 或 `--all` 汇总）。创建新作品时由 `scripts/create_project_skill.py` 自动一并创建该剧 `启动制作看板.cmd`，不复制 `tools/studio` 程序代码；无正式数据时显示空状态。动态分镜页和静态HTML共用导出器。制作数据是本集分镜、提示词及素材绑定的唯一来源，专属技能提供跨集创作方法与设定引用；不另外落盘待执行计划、series或审核台账。

工作台默认在原分镜看板上原位编辑中文，点击「播放版本」按需打开右侧贴边非模态对照抽屉；视频版本星标（`⭐`/`❌`/备注）与单镜审阅标记独立保存在工作台 `审片标注.json`，不修改 `制作数据.json` 哈希。用户保存的待同步修改在当前单元或组合段的 `editor_draft.values`，并以 `state: pending_sync` 禁止付费提交。收到“同步提示词”或「汇总待同步」请求时先读取此草稿，以用户最新中文（含 `chinese_description` 完整中文正文）为准，同步中文字段及当次模型正文、对白、时长和实际切点；H3 同步 `prompt_zh` 与完整英文六段，Wan3/SD2.0 同步 `generation_groups` / `seedance_groups` 的 `prompt_text`、`shots`、`dialogue_events` 及源修订，主段仍固定 30 秒 / 15 秒。核对图序及前后段接点，再清除对应草稿并联审/导出；不要只清标记或改时长。同步不代表付费授权，也不触发未经用户要求的补镜。编辑保存使用逐段版本校验，冲突时保留用户输入。既有任务快照和视频历史不改。

每次提交分别核对模型、服务商、模式、时长与输入能力，再使用对应接口和本次密钥（可在「提交接口」弹窗选填可选预估单价用于预算统计）。未接入的模型需先在 `tools/studio/upstream.py` 实现相应正文与适配器并以模拟测试验证，再在获授权后实际验证；不能把新模型写进无关映射或只改域名冒充接入。模型不可用时不允许自动跨模型重发，未获用户处理要求也不自动创建 H3 补镜。

先按一次联审流程完成 reviewed；用户明确终审通过后将原制作数据的 review_status 更新为 user_approved。当次模型完整正文、真实已核验图片、现行原件、实际适配与用户批准均满足才可登记生成。点击「提交 / 重提本集」（或任务页失败重提）可勾选现有支持的镜头；确认页按实际选中镜头展示模型、时长、总秒数与可选预估费用，确认按钮授权本次付费任务，由队列自动限流等待、轮询、下载并保存视频新版本。

Agent后续也走同一队列，不另写提交脚本。读取对应作品服务 `/api/state` 获取剧集ID，再运行（默认为只预览，不写队列，传入 `--project <作品目录名>` 自动定位该剧端口）：

```powershell
python tools/studio/submit.py --project <作品目录名> --episode <剧集ID> --units U01 U02 --profile <接口ID>
```

当用户已明确授权本批付费生成时加 `--execute`；可用 `--key-env <环境变量名>`，或使用已在本次服务内存中输入的密钥。命令行和制作数据中不写密钥值。程序不应要求用户对已经明确授权的同一批次反复确认。

提交时冻结当次模型与接口、完整正文、实际时长、图片顺序及SHA256、源稿修订；修改制作数据不改历史任务。超时或5xx结果不明确时先核对原接口任务列表，唯一匹配可恢复，未能匹配不自动重发。未确认失败不盲目重复付费提交，不自动跨模型重试。服务重启后重新输入旧任务原接口的密钥即可恢复查询下载。关闭网页不停止本地后台。

运行数据按作品分别写入各自 `<作品名>/制作资料/制作看板/`（汇总模式下写入根目录 `制作资料/制作看板/`）：接口配置不含密钥、审片标注与剪辑方案独立持久化、任务快照用于恢复、导出记录用于产物定位；不再另写工作日志或审阅报告。空闲无任务不持续生成队列记录，同内容状态不重复改写。视频进入对应剧集 `生成视频/看板重提/`，保留各版本；混剪支持版本标星优先选用、`I`/`O` 快捷键设入出点、排序、连续预览、MP4 与 `.srt` 字幕导出。
