# 打戏与仙侠特效：按本场需要取用

本页用于各模型共用的场面、动作与特效设计。提示词统一执行主技能八条创作约束与[当次模型规范](model-routing.md)，只提交当前生成段完整的正向声画描述；切换模型不重新设计能力或特效，不自动开启补镜。

先读完整攻防而非逐招配特效。由原件确定双方动机、能力边界、目标、风险、场地和胜负变化。让每次回应改变下一步：进攻被挡如何变向，闪避怎样改变距离，受击怎样影响支撑与后续动作。原件只有结果时可补合理的执行过程，但不新增能力、神器、伤亡、胜负或改变攻击性质。关键设定缺失留待决定项。

## 三大打戏实战模板引擎（`combat_mode`）

凡涉及正面对决、打斗或大场面冲突的生成单元，必须在制作数据中声明 `combat_mode` 并按对应低成本高出片率公式编排（严禁凭空写让视频模型必崩的连环虚招）：

| 打戏引擎 (`combat_mode`) | 核心防崩策略（适配低成本少抽卡） | 强制镜头与节奏公式 |
| --- | --- | --- |
| **近身格斗 / 冷兵器拆招**<br>`melee` | **严禁写“拳脚如雨、连招十余、连续格挡多次”**（AI必出现多手多脚融化）；拆为**单次硬碰 + 空间借物破坏**（撞碎木桌/墙柱/玻璃比打空气出片率高3倍） | 中全景确立左右站位与攻向 → 动中硬切特写（兵刃/手腕接触点+火星+短顿）→ 侧跟/低仰拍展示击飞撞碎场景物件 |
| **仙侠术法 / 异能对轰**<br>`vfx_duel` | **防白光糊脸**：单镜最多 **2层主特效**（1主形制 + 1环境受光），写清剑气剖面/符环/锁链等轮廓与暗部留白；**禁写“对波僵持10秒”“万道金光淹没”**，改写单向压制或一招破阵 | 敌方术法压境（强冷暖染脸）→ 主角起手结印/拔剑特写 → 广角一招劈开阵雾、气浪向两侧掀翻地砖衣摆、稳住冷峻正面 |
| **巨物压迫 / 以一敌多**<br>`boss_crowd` | **严禁同时描写5个以上杂兵独立招式**（必穿模融人）；强制采用**“主角中心爆发 + 外围杂兵统一呈放射状向画面边缘掀飞/溃退”**的群体矢量写法 | 极低角度广角仰拍（前景渺小主角剪影衬托巨物压迫）→ 震地冲击波由中心向外扩散 → 群体统一失衡后撤 |

## 打斗换位防越轴与持械锁（`combat_axis`）

凡打戏单元（设置 `combat_mode` 或 `is_combat: true`）**必填 `combat_axis`**（例如：`"起态：林昊画左(右手持刀) ⇄ 反派画右(空手) ｜ 换位：镜2全景滑铲绕至画右"`）：
1. **同回合攻向恒定：** 同一回合内攻击方向锁定（如画左攻向右，对手必向画右格挡或倒飞）；
2. **全景显式换位禁硬切跳边：** 需要双方互换画面左右时，必须在**全景或中全景**中完整拍出人物横向越过中线的移动过程，严禁在近景/特写硬切后突然左右互换；
3. **主手兵器全段锁死：** 明确武器在左手还是右手，除非在镜头内明确拍出“脱手/换手”，否则全段严禁左右手乱跳。

## 打击感翻倍配方：顿帧感与四层战斗音效

1. **打击顿帧感（Hit-stop）写法：** 命中刹那禁止只写“流畅打过”，必须写明**“接触瞬间短暂停顿压实 + 火星/尘土/衣袂炸开 + 镜头随受击短促微震并迅速回稳 + 对手失衡撞物”**，彻底消除AI打戏“发飘没重量”的通病。
2. **四层战斗音效绑定（禁写笼统的“激烈打斗声”）：** 按实际动作时点落到四个声响层次——
   - ① **起势破风**：刃风尖啸 / 衣袍猎猎 / 蓄力低频嗡鸣；
   - ② **接触爆裂**：金铁交鸣 / 拳肉闷响 / 护盾脆裂；
   - ③ **环境破坏**：木桌炸裂 / 墙石剥落 / 玻璃碎溅；
   - ④ **余波留白**：受击闷哼 / 急促喘息 / 烟尘落定瞬间死寂，顺势切入反杀金句。

## 攻防推进与情绪爆点

每次攻击明确当前目的，防守或反制改变距离、支撑、路线、资源或优势，进而触发下一行动。重复交手必须体现新进展，不把同一招换颜色、放大光效就当作升级。按原件呈现优势建立、动摇与反转，让观众看懂转折由什么动作或既有能力造成；不固定每场都先败后胜。

力量峰值把注意力集中到关键动作、受力结果和对手反应。摄影、声音与特效共同强化同一次作用，不各自争抢爆点；先让命中与变化可读，再进入后续攻防。高潮后保留原件中的战损、位置改变、关系变化或未消除威胁，不打完归零。不套统一“蓄力—对轰—爆炸”，也不以强制肉搏比例替代术法逻辑。

## 身体、接触与摄影

可见动作写清起力的支撑点、重心和传导、身体或武器路径、目标、接触及受力结果；取本镜确实看得见的细节，不每个动作强塞同一发力链。腾空说明起跳与落点，防守说明挡在哪里、退向哪里，远程术法保留施术与对方回应，不强加肉搏。

Wan3的30秒主生成段内按复杂度安排可读的动作过程及回应，可用数秒内部镜头交接，不把整段都写成一个持续爆炸，也不把每个动作阶段都拆成独立请求。按实际发展连续写清发动、接近、接触、作用及接续，不用固定时间格拆招。攻击、相机和特效可以同时发展；动作快慢来自处境，不统一蓄力、慢镜、停顿、收招。切点可在动作中间，但下一镜或下一生成段不得再命中一次。复杂度本身不授权切模型；H3只有用户提出处理瑕疵后才设计局部补镜。

摄影先让空间与力量方向可读，再表达速度与压迫。全身或中景保留必要重心和接触，局部特写用来揭示有用细节；震动须由命中、地面冲击等触发，余震衰减，不持续随机抖动。巨物体量用已有参照、遮挡、视差和落地反馈体现，不只写“大、震撼、电影级”。

## 特效全过程

特效与光效采用对应的专业术语：自发光（emission）描述发光载体，辉光（bloom）描述高亮向邻域的扩散，粒子发射与拖尾描述运动轨迹，体积散射描述光与介质的作用，遮挡、反射、折射与交互光描述其对人物和环境的可见影响。按当前效果写出术语对应的形态、位置、强度变化与作用对象。

对本镜已有法术、剑气、法阵、法相、变装等，明确：起源与载体 → 形状/材质形成 → 方向、速度与空间扩展 → 和目标的交互 → 消散或保留状态。只写适用阶段，不机械凑五段。多个效应先确定主次与发生时点，避免满屏光吞掉身体动作和因果。

材质、颜色、边缘、密度、尺度与透光性按当前设定；原文未细写时，由导演补足不改变能力的视觉表现。用户要求补齐特效美术即授权设计相应形制、材质、纹路、轨迹、节奏和交互，不等原文提供完整特效词，但不能把普通推力写成燃烧或切割。光效照亮人物与现实背景时保持同一光向、遮挡和反射；烟尘、布料、碎屑与冲击方向一致。先写实际可见的受力与环境变化，再补声音的起点、峰值、衰减与远近。

变装按选定的转场方式编写：渐变写出变化沿何部位推进、尚未变化处保留什么；动作匹配硬切写清切前动作阶段、准确切点和切后完成态，衣装与场景需要同步时在同一拍完成。环绕时人物不为跟相机而自转。法阵写清朝向、空间位置及人物关系，不能用新增宗教符号或文字替代原件。风格化冲击帧仅在剧情与导演设计需要时选用，注明短暂变化及返回接点，不统一强制黑白闪。

## 特效美术设计与跨模型一致性

先确定这一能力在本镜的视觉特征，再组织全过程。按实际效果选择需要明确的内容：主轮廓与内部结构，材质厚薄、透明度及折射，亮核与暗部的体积，局部高光与边缘过渡，疏密、留白和尺度变化，以及形成、加速、峰值、残留和消散的节奏。不要把术语或“高级、震撼、金光闪耀”当成设计，也不靠堆加无关特效丰富画面。发光之外仍应有能辨认的形体、材质和运动；自发光、辉光与照亮环境是不同作用。

结合当前构图选择视觉主次：人物表演、接触点或核心特效承担注意力，其余层次在亮度、密度、尺度和运动幅度上配合。主次随剧情转移，不固定效果数量；峰值过后保留可读结果，持续光效不能吞掉人物脸、手部接触或下一动作。交互光、反射、遮挡和景深服从同一真实空间，不把整场均匀染亮。审美判断同时看整体构图与连续播放，单帧亮丽不代表运动好看。

### 将粒子系统思路转成修仙画面

可借鉴Niagara等特效制作中的形体、材质、粒子、带状拖尾与运动组织，但不能把“Niagara实时粒子系统”“Emissive分层渲染”“Motion Sample”当作视频模型会执行的引擎开关。模型正文写它们对应的可见结果；准确术语可辅助，不能替代设计。

- **先定本法术的形。** 修仙感从当前人物与能力适用的符箓笔势、云篆、金石刻纹、玉质法器、墨气或剑气剖面等具体形制中选择，形成一致的视觉语言。地面法阵、弓弦凝光、刃部裹光只是不同载体的例子，不能按法师、射手、战士三类机械套用，也不把普通动作都加上法术。虚构纹路服务画面，原有可读文字、宗教符号和能力设定不擅改。
- **再定形体怎样受光。** 指定承载发光的花脉、刻槽、刃脊或符纹，亮核集中于关键部位；中层仍看得见半透材质、厚薄、折射与背光暗面，外层辉光范围收敛。自发光、外溢辉光、照亮环境分别描述，不能用更强的白光把形体抹掉。
- **节奏来自运动与作用。** 根据施术动作设计凝聚、快速释放、展开或命中、减速、余势和收束，适用哪些写哪些。主形体先形成，附属碎屑或流纹按不同速度跟进；拖尾沿真实路径弯曲，前端有形、尾端渐细渐散，停下后按惯性短暂追随。Ribbon式带状拖尾是实际残迹，Motion Blur运动模糊是速度的成像表现，时域采样是渲染方法；增加模糊本身不会产生动作节奏。
- **交互服从剧情物理。** 环境响应落到具体对象的受光、折射、遮挡、反射或受力，不凭空加爆炸、破坏和伤亡。凝时场面中，已冻结的火雨、烟尘不能又被法术风场吹动；可让法术的光影在凝住的雨滴与湿石上变化，施术者及其术法按设定继续运动。

在既有第4项联审中检查：暂时略去“金光、发光、光线”等词，本镜是否仍有可辨造型、内部纹路与材质、动作触发及明确运动节奏；再查这些形体是否仍给脸、手与接触点留出观看空间。检查结果回写当前分镜与实际提交正文，不另造只供内部看的特效表。

同一能力跨集、跨模型重复时，沿用已确认的造型、材质、运动和光影特征；长期选择放项目技能，具体触发、规模和摄影写入当前制作数据。设计或推定未获用户确认时表明依据，不把一次抽卡的偶然外形自动固定为设定。模型提示词只转写当前已审设计，不输出内部术语编号或编写项目清单，也不因换模型改变能力性质。H3补镜的特效与原Wan3合格片段对齐，用户未要求处理时只说明观察到的问题。

方法参考：[cinematic-vfx-director](https://github.com/snowfrost/skill-movie/blob/main/cinematic-vfx-director/SKILL.md)的视觉层次与[修仙特效语言](https://github.com/snowfrost/skill-movie/blob/main/cinematic-vfx-director/references/supernatural-vfx-language.md)，以及[vfx-effect-construction-engine](https://github.com/snowfrost/skill-movie/blob/main/vfx-effect-construction-engine/SKILL.md)的造型、材质与运动构建。仅采用适用方法，不导入其依赖链、固定特效数量、Seedance专用编译或自定义六段格式，不安装或执行外部代码；模型语法仍取当次官方指南。

技术释义依据Epic官方文档：[Niagara实时特效系统](https://dev.epicgames.com/documentation/en-us/unreal-engine/creating-visual-effects-in-niagara-for-unreal-engine)、[Emissive自发光与环境照明](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-the-emissive-material-input-in-unreal-engine)、[Ribbon带状粒子](https://dev.epicgames.com/documentation/en-us/unreal-engine/create-a-ribbon-effect-in-niagara?application_version=4.27)和[运动模糊与时域采样](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-motion-blur)。借鉴可见结果的组织方法，不声称视频服务运行这些引擎设置。

## 统一审阅时检查

先查动作与因果：攻防是否带来进展、爆点结果是否可读、特效是否作用于正确对象、尺度和状态是否连续、动作与声音是否容得下。再查美术：轮廓与内部结构是否清楚、材质有无厚薄和明暗、疏密和发光是否有主次、运动有无节奏、人物表演及环境交互是否可读，不能“效果都出现了”就判通过。文案问题修本段及相邻接点；成片问题依据实际播放指出，不自动触发付费重试或H3处理。模型正文统一按八条创作约束及[对照审核](h3-prompt-practice.md#官方对照审核)检查，实际生成后再核验执行结果。
